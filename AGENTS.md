# AGENTS.md — Vayu

Context file for any agent or contributor working in this repository. Read this before changing code.
It records the product intent, the non-negotiable rules, the actual architecture, and the verification
commands. If code and this document disagree, treat the code as the source of truth and update this file.

---

## 1. What this project is

**Vayu** ("wind") is a GenAI-powered urban air-quality and family-protection assistant built for
Hack2Skill PromptWars Challenge 6. It is a real, deployable application — not a landing page or a fake
dashboard.

The product problem: help families and communities navigate severe winter smog and urban air pollution by
suggesting low-emission daily routines, indoor-air improvements and sustainable alternatives tailored to
their location and lifestyle, while explaining the direct impact of their choices.

The repository was originally a single-file prototype (`src/App.tsx`) with hardcoded readings, US AQI
breakpoints mislabelled as CPCB, dead buttons, and no AI or API wiring. It was rebuilt into the modular
app described below. Old branding (AirAware) and demo data were removed deliberately.

## 2. Non-negotiable rules

These are product-correctness rules, not style preferences. Breaking one is a bug.

1. **Never fabricate an environmental reading.** No hardcoded AQI, PM2.5, temperature, station name or
   observation timestamp. If a provider fails, show an explicit unavailable state and the last known
   timestamp. Never substitute demo data into the live dashboard.
2. **Never label a model estimate as official.** Open-Meteo/CAMS values are model fields. CPCB/data.gov.in
   values are official observations. They are displayed in separate cards with different labels and are
   never merged into one number.
3. **AQI is computed, never generated by an LLM.** Gemini may explain and prioritise; it may not calculate
   AQI, emissions, exposure or risk. All numbers come from deterministic TypeScript functions.
4. **Follow CPCB methodology.** Overall AQI = maximum valid sub-index (not an average). Requires at least
   **3 valid pollutants including PM2.5 or PM10**. Values beyond the published scale are capped at 500 and
   flagged, never silently clipped.
5. **No invented impact numbers.** If a defensible factor does not exist, the UI says so and shows a
   qualitative benefit. Household/community alternatives carry no kilogram claims. No cigarette
   equivalence claims. Uncertainty ranges are shown where factors are approximate.
6. **Never imply instant city-wide change.** Personal emissions avoided ≠ outdoor concentration ≠ personal
   exposure. A mode shift does not "fix the AQI", and the UI says that.
7. **Health safety.** No diagnosis, no prescription, no "replace your doctor". Never recommend ozone
   generators, unsafe DIY electrical filtration, or houseplants as a substitute for filtration. Never
   blindly advise opening windows during high outdoor pollution.
8. **Privacy.** No names, exact birth dates, diagnoses, medical records or exact GPS coordinates. Only
   non-identifying preference categories are stored (localStorage) and sent to the AI service. The shareable
   summary (`utils/share.ts`) carries public model values only: it excludes the household-specific
   recommendations (school, older adults, outdoor worker) so a forwarded message does not disclose who lives
   in the home.
9. **Deterministic fallback always works.** With no `GEMINI_API_KEY`, no network, or a provider outage, the
   planner, chat and official-data paths degrade to labelled deterministic behaviour instead of breaking.
10. **Secrets stay server-side.** API keys are read only inside `api/*` handlers via `process.env`. Nothing
    key-shaped is ever returned to the client.

## 5. Data flow

### 5.1 Model path (always available)

```
AppProvider(location) → useAirQuality → fetchAirQuality(location)
  ├─ GET air-quality-api.open-meteo.com/v1/air-quality
  │    current + 2 days hourly, timezone=auto
  ├─ GET api.open-meteo.com/v1/forecast (weather; failure is non-fatal)
  └─ valuesFromCurrent → assessAqi(values,'model') → ModelSnapshot
       → cache 10 min keyed on 2-decimal coordinates
```

- `carbon_monoxide` arrives in µg/m³ and is divided by 1000 for the CPCB CO breakpoints (mg/m³).
- Hourly timestamps are **location-local strings without an offset** (`2026-11-18T14:00`). Never pass them
  to `new Date()`. Use `formatHourLabel()` and string comparison (`startIndexFor`).
- Hourly series starts at the current hour and holds up to 24 points. Points with insufficient coverage get
  `aqi: null`; they are never interpolated.

### 5.2 Official path (optional, best-effort)

```
fetchAirQuality → fetchOfficialAqi(city) → GET /api/aqi?city=…
  api/aqi.ts → api.data.gov.in/resource/{DATA_GOV_IN_RESOURCE_ID}?api-key=…
    → normalize(): prefer a usable AQI field (0–500). Otherwise group
      pollutant-only rows (pollutant_id / avg_value) by station and return the
      most complete station as official concentrations.
    → retry once with the trailing place name ("New Delhi" → "Delhi") when the
      exact city returns no rows
    → cache 10 min (available) / 3 min (unavailable)
```

The default resource is the CPCB "Real time Air Quality Index from various locations" dataset
(`3b01bcb8-0b14-4abf-b6f2-c1bfd384ba69`). Despite the title it has **no AQI field**: it publishes one row per
pollutant per station. Those rows are official observations, so they are shown as official **station
concentrations** alongside the station name and `last_update`.

Hard rules in `normalize()`:

- an official AQI is returned **only** when the provider actually supplies one;
- pollutant-only records are never converted into an "official AQI";
- CO is surfaced with `unit: 'as published'` because the dataset does not state its unit;
- placeholder values (`NA`, `-`) are dropped, never zeroed.

Client-side `OfficialSnapshot` re-validates the shape with Zod, rejects out-of-scale AQI values and requires
finite pollutant concentrations.

### 5.3 AI path (optional, never authoritative)

```
Chat:  AIAdvisor → askVayu() → POST /api/chat → Zod validate → Gemini → Zod validate → {answer, sources}
       any failure → fallbackChatAnswer() (intent-based, uses real context values)
Plan:  DailyPlanner → requestAiBrief() → POST /api/plan → Zod validate → Gemini → Zod validate
       any failure → {source:'unavailable', reason} → deterministic plan stays on screen
```

Gemini never sees secrets, never receives household names, and its output is bounded and validated.
Section titles in `/api/plan` are a closed enum, so a hallucinated section is rejected wholesale.

Both handlers call Gemini through `callGemini()` in `api/_lib/gemini.ts`: one overall 18 s deadline and
**one retry** for transient overload (`503 UNAVAILABLE`, `429 RESOURCE_EXHAUSTED`, 5xx). The live model
intermittently rejects under load, so a single retry turns a visible fallback into a real answer, while real
configuration faults (400/403) fail immediately. If every attempt fails, the deterministic path above runs
unchanged. Provider errors are logged server-side only.

### 5.4 Derived UI state

```
air.data.model.assessment + hourly + profile
  → buildPlanner({assessment, hourly, profile})   [memoised in AppContext]
      → recommendations, bestWindow, worstWindow, contextSummary
  → checklist (per local date) toggles recommendation ids
  → AIAdvisor.suggestionsFor(category, profile)   [question set follows today's reading + household]
  → DailyPlanner.actionLink(category)             [commute → /impact, indoor/night → /indoor, else → /air-quality]
  → buildShareText({city, assessment, planner})   [public values only; household-specific ids excluded]
```

## 6. AQI methodology

`src/constants/aqi.ts` holds CPCB breakpoints; `src/utils/aqi.ts` implements the maths.

| Pollutant | Unit | Averaging | Breakpoints | Sub-index thresholds |
| --- | --- | --- | --- | --- |
| PM2.5 | µg/m³ | 24 h | 0, 30, 60, 90, 120, 250, 500 | 0, 50, 100, 200, 300, 400, 500 |
| PM10 | µg/m³ | 24 h | 0, 50, 100, 250, 350, 430, 600 | same |
| NO₂ | µg/m³ | 24 h | 0, 40, 80, 180, 280, 400, 600 | same |
| SO₂ | µg/m³ | 24 h | 0, 40, 80, 380, 800, 1600, 2000 | same |
| CO | mg/m³ | 8 h | 0, 1, 2, 10, 17, 34, 50 | same |
| O₃ | µg/m³ | 8 h | 0, 50, 100, 168, 208, 748, 1000 | same |
| NH₃ | µg/m³ | 24 h | 0, 200, 400, 800, 1200, 1800, 2400 | same |
| Pb | — | — | **not modelled** | Declared out of scope: a filter-based 24 h measurement that CAAQMS networks do not report continuously. The app implements 7 of CPCB's 8 pollutants and says so in `docs/DATA_METHODOLOGY.md`. |

Sub-index = linear interpolation inside the bracket, rounded to an integer.
Overall AQI = `max(valid sub-indices)`, capped at 500. Coverage: ≥3 valid pollutants **and** at least one of
PM2.5/PM10, otherwise `status: 'insufficient-coverage'`, `aqi: null`, with a human-readable reason.

Because provider values are instantaneous CAMS model fields, the result is always labelled
**"estimated CPCB-style model AQI"**. The averaging-period column is shown so the mismatch is explicit.

## 7. Impact calculations

`src/utils/impact.ts` is the only place allowed to produce numeric impact values.

- `TRANSPORT_FACTOR_VERSION = 'vayu-planning-2026.1'`, displayed next to every result.
- Factors are kg CO₂e per passenger-km: metro 0.041, bus 0.089, carpool 0.192 (÷ occupants), petrol car
  0.192, two-wheeler 0.103, walking/cycling 0.
- Annual = oneWayKm × 2 × daysPerWeek × 52 × factor. ±20% uncertainty band is shown.
- `exposureProxy` = PM2.5 × hours, unit µg/m³·h. Explicitly **not** inhaled dose or medical risk.
- `estimateCadr` = room volume (m³) × air changes/hour (4–5, or up to 6 for vulnerable households).
  A sizing calculation, not a predicted indoor concentration.
- Household and community alternatives in `src/constants/alternatives.ts` are qualitative by design and are
  covered by a test that fails if a kg/tonne figure is added to them.

## 8. AI contracts

### `POST /api/chat`
Request: `{ message ≤800, location:{city,aqi|null,pm25|null}, preferences?:{commute,vulnerable,budget}, forecast?:{category,bestWindow,worstWindow} }`
Response: `{ answer: 1–1800 chars, sources: string[] ≤5 }`
Rate limit 20/min/client. Body cap 12 kB. Prompt bounds context and marks user text as untrusted inside
`<user_question>`. Any Gemini error, empty text or invalid shape → deterministic fallback with HTTP 200.

If `classifyChatIntent()` returns `unknown`, Gemini is **not called at all** — the deterministic refusal
answers. That is deliberate (cost, and no model gets to answer an out-of-scope question), but it means a new
legitimate question type stays unrouted until it is added to the classifier. Every added intent needs an entry
in both `answers` and `INTENT_TERMS` (the compiler enforces it).

`inspectAiText()` rejects, among other things, any numeric CO₂/emissions figure: per-km factors live in
`src/utils/impact.ts` and the model must not do that arithmetic. The rule matches numbers, not the word, so
"Vayu computes CO₂e in the Impact simulator" is allowed while "saves about 2.3 kilograms of CO2" is not.

### `POST /api/plan`
Request: `{ location:{city,aqi,category,pm25}, windows:{best,worst}, profile:{adults,children,elderly,outdoorWorker,vulnerable,commute,budget,hasPurifier,roomAreaSqFt} }`
Response (AI): `{ source:'gemini', greeting, sections[1..8]{title∈enum, guidance 10–600}, sources }`
Response (no AI): `{ source:'unavailable', sections:[], reason }`
Rate limit 10/min/client. Body cap 16 kB. The request schema is `.strict()`: an extra field is a 400 and every
listed field is required, including `category`, `vulnerable`, `hasPurifier` and `roomAreaSqFt`. There is **no**
`deterministicActions` field — the handler never consumes it, and the deterministic plan stays client-side.
Prompt forbids contradicting that plan.

`greeting` is capped at 160 characters. The live model routinely returns ~180, so the handler clamps it at
a word boundary (`normalizeBrief`) rather than throwing away a brief whose sections are all valid. Section
titles are **not** relaxed: an unknown title still rejects the whole brief, because a title outside the enum
means the model invented a section type rather than merely overshooting a length.

Because of that, the prompt must show the model the enum: `allowedTitleList` is interpolated into the system
instruction **and** the same titles are passed as a `responseSchema` enum (`geminiBriefSchema`). Without both,
the live model invents headings such as "Current Conditions" and every brief is discarded — a silent 100%
fallback that unit tests cannot see, because they mock the model. Do not "simplify" the prompt by removing
the title list. Likewise `inspectAiText()` ignores pattern matches inside a negated clause: the model writes
"avoid any improvised filtration devices", which the naive match read as a DIY recommendation.

Rejections are logged server-side as `[api/plan] rejected AI brief: [{"title","codes"}]` — title and rule code
only, never the household profile. Check the deployment logs when the AI brief is missing.

### `GET /api/aqi`
Response: `{ available, aqi|null, station|null, distanceKm|null, observedAt|null, provider, reason|null, pollutants[] }`
where `pollutants[] = { id, label, value, min|null, max|null, unit }` (max 12).
`available: true` with `aqi: null` means the provider returned official concentrations but no AQI.
Rate limit 60/min/client. `Cache-Control`: 10 min when available, `no-store` when not.

Changing any of these shapes requires updating: the Zod schema in the handler, the client parser
(`chatService.ts` / `planService.ts` / `officialService.ts`), the tests, and this section.

## 9. Development quirks and gotchas

- **`npm run dev` does not serve `/api/*`.** Vite has no serverless runtime. The client handles the 404 and
  shows an explicit unavailable state. Use `vercel dev` to exercise the API functions locally.
- **Vercel's `nodejs` runtime calls handlers as `(req, res)` with Node objects.** The handlers are written
  Fetch-style (`Request` in, `Response` out) so they can be unit-tested, so every `api/*.ts` default export
  is wrapped in `withVercelRuntime()` from `api/_lib/adapter.ts`. Without that wrapper the deployed function
  throws `TypeError: request.headers.get is not a function`. Unit tests inject a real `Request`, so they pass
  either way — the adapter is the only thing that catches this class of bug.
- **Every file under `api/` becomes a serverless function**, except paths that start with `_`. Shared helpers
  therefore live in `api/_lib/`, and `api/**/*.test.ts` is excluded via `.vercelignore`, so neither is
  published as an endpoint. Confirm with `vercel inspect <deployment-url>`: only `api/aqi`, `api/chat`,
  `api/plan` and `api/health` should be listed.
- **Every `src/` import reached from `api/` must carry an explicit `.js` extension.** This is not style. The
  Vercel functions run on Node's ESM loader, which does not resolve extensionless specifiers, so
  `from '../constants/sources'` crashes the function at link time with `ERR_MODULE_NOT_FOUND` *before any
  handler code runs* — every method returns 500, including `GET`. Vite and Vitest both resolve it happily,
  so the unit suite stays green. This exact bug took `/api/chat` and `/api/plan` down in `6003d38`; it is
  why `npm run smoke` exists. `import type` is erased at build time and is safe either way.
- **`npm run smoke` is the only test that exercises the deployed module graph.** Unit tests import handlers
  in-process, so they cannot detect a link-time failure. Run it after every deploy.
- **Open-Meteo timestamps have no offset.** See §5.1. This is the most common source of subtle bugs.
- **CO units differ.** Open-Meteo µg/m³ → app mg/m³. Do not "fix" the division.
- **Missing weather fields stay `null`.** `WeatherNow.humidityPct` and `windKmh` are `number | null` and render
  as "Unavailable". Never coerce them to `0` — that would fabricate a reading.
- **Coordinates are quantized to 2 decimals** (`quantizeCoordinate`) before storage and cache keying, so
  exact GPS is never retained. Do not store raw `position.coords`.
- **Cache is in-memory and per-process.** Serverless instances do not share it. That is intentional (no
  database, no cross-user leakage).
- **Rate limiting is per-instance.** Good enough for abuse damping, not a billing guarantee. The shared
  Upstash path in `api/_lib/rateLimit.ts` is implemented but no `UPSTASH_*` variables are configured in
  production, so `checkSharedRateLimit()` returns `null` and the in-process `Map` is the only limiter. The
  documented 20/min is therefore per lambda instance, not global. Do not describe it as global.
- **Lead (Pb) is not modelled.** CPCB's AQI table covers eight pollutants; this app implements seven
  (PM2.5, PM10, NO₂, SO₂, CO, O₃, NH₃). Pb is a filter-based 24 h measurement that CAAQMS networks do not
  report continuously, so it is declared out of scope rather than silently dropped. See
  `docs/DATA_METHODOLOGY.md`.
- **The Vercel project Node version is `26.x`, which local CLI 56 rejects.** `vercel build` and `vercel dev`
  therefore fail locally on this host ("invalid or discontinued Node.js Version"); the build machine uses
  CLI 65 and builds fine. `vercel dev` additionally crashes with a libuv assertion on Windows. Use the
  production logs (`vercel logs --status-code 500 --json`) to diagnose runtime faults instead.
- **Gemini returns `503 UNAVAILABLE` intermittently.** It is upstream capacity, not a bug in the prompt. Both
  endpoints retry once via `callGemini()`; do not remove that retry to "simplify" the handler, or the demo
  will show the fallback card at random. Do not add retries for `400`/`403` — those are configuration faults.
- **`dist/` is generated.** Never edit it; it is gitignored.
- **Windows PowerShell 5.1 misreads BOM-less UTF-8.** Em dashes and smart quotes become string delimiters and
  break parsing. Keep `scripts/*.ps1` pure ASCII.
- **PowerShell strips quotes from inline JSON** passed to `curl.exe`, producing `400 INVALID_ARGUMENT` from
  Gemini. Write the payload to a file and use `--data-binary "@file"`.
- **Secondary text goes through two audited tokens, never a raw grey.** `--muted` (#626c65) is ≥4.8:1 on
  white, cream and the tinted panels; `--muted-strong` (#4f5b53) is ≥6.2:1 and is used for the 8–9 px
  uppercase labels and eyebrows. Light-on-dark text (`.brand-mark`, `.mask-card`) is measured against a dark
  surface and keeps its light colour — do not "fix" it to a token. If you add a colour, compute the ratio
  first; the previous draft shipped 20+ greys at 2.6–4.3:1.
- **Use the shared page primitives instead of re-writing the markup.** `PageHeading`, `RefreshButton`,
  `KeyReadings`, `AqiGauge` and `SourceLinks` exist because eight pages had drifted: three refresh labels, two
  source-list renderers, two `as React.CSSProperties` casts and two copies of the chip list. A new page composes
  them; it does not copy the old JSX.
- **`src/index.css` is an append-structured stylesheet.** Several components have an early rule and a later
  "visual refresh" rule; later wins. When changing a visual value, grep for every declaration of the selector
  first, or the edit will be silently overridden.

### Storage keys (client only)
`vayu.profile.v1`, `vayu.location.v1`, `vayu.checklist.v1`, `vayu.onboarded.v1`.
All reads are schema-validated; corrupt or legacy values fall back to defaults. `resetAllData()` removes
every key and restores in-memory defaults.

## 10. Testing conventions

- Runner: Vitest. `jsdom` for `src/**`, node environment for `api/**` (`/* @vitest-environment node */`).
- Config: `vitest.config.ts` (includes coverage thresholds), setup: `src/test/setup.ts`.
- Test files sit next to the code: `foo.ts` → `foo.test.ts` (or `.tsx` for components).
- Every test must clean up: the setup unstubs globals and clears localStorage after each test.
- Mock `fetch` with `vi.stubGlobal`, not module patches, except `@google/genai` which is mocked with
  `vi.hoisted` + `vi.mock` in the API tests.
- Coverage scope is `src/utils`, `src/services`, `src/constants`, `api/**`. Page/component rendering is
  covered by `src/App.test.tsx` and `src/components/*.test.tsx`, not by the coverage gate.
- Assertions must be about real behaviour: computed numbers, provenance labels, explicit unavailable states,
  and "no fabrication" guarantees. Snapshot tests are not used.
- Privacy tests assert the *absence* of household detail in outbound text. `src/utils/share.test.ts` fails if
  `buildShareText` starts including a household-specific recommendation, a profile value or a coordinate.

## 11. Deployment

Live: **https://vayu-wheat.vercel.app** (Vercel project `prashant-singhs-projects-4b5930a2/vayu`; `vercel.json` configures functions for `bom1`).

The project is linked to GitHub `PrashantDevX/Vayu_Hack2Skill`, so **every push to `main` deploys to
production automatically** and every other branch produces a preview deployment.

1. Import the repo, framework preset Vite. Build command `npm run build`, output `dist`.
2. Set environment variables (all optional — the app degrades honestly without them):

| Variable | Purpose |
| --- | --- |
| `GEMINI_API_KEY` | Enables AI chat and AI daily brief |
| `GEMINI_MODEL` | Overrides the default `gemini-3.5-flash-lite` |
| `DATA_GOV_IN_API_KEY` | data.gov.in API key for official AQI |
| `DATA_GOV_IN_RESOURCE_ID` | data.gov.in resource id for the CPCB-linked dataset |

3. `vercel.json` supplies SPA rewrites and security headers (CSP, HSTS, `X-Frame-Options: DENY`,
   `nosniff`, referrer policy, permissions policy). If you add a provider domain, add it to `connect-src`.
4. `.vercelignore` keeps `api/**/*.test.ts`, `coverage/`, `docs/` and `scripts/` out of the upload, so test
   files are never published as serverless endpoints, and shared helpers live in `api/_lib/` (underscore
   prefix = not a function).
5. **Functions must run in `bom1` (Mumbai).** `vercel.json` sets `"regions": ["bom1"]`. data.gov.in is served
   from NIC and refuses connections from Vercel's default `iad1` region with `ECONNREFUSED
   164.100.61.198:443`. Deploying to the default region makes the official card report "temporarily
   unavailable" in production while working perfectly locally — a confusing failure worth knowing about.
6. **Deployment protection must stay off** for a public demo. New projects can default to
   `ssoProtection.deploymentType = 'all_except_custom_domains'`, which makes every `*.vercel.app` URL
   redirect to a Vercel login. Clear it with
   `PATCH https://api.vercel.com/v9/projects/{projectId}?teamId={orgId}` and body
   `{"ssoProtection": null}`.
7. Verify `/api/health` reports the expected configuration flags.

`npm run check:providers` validates the upstream credentials, but it does not exercise the deployed
functions. Always smoke-test `/api/health`, `/api/aqi`, and one `POST /api/chat` after a deploy.

## 13. Known limitations

- **Official data needs a personal data.gov.in key.** The default resource is the CPCB real-time dataset,
  which publishes station concentrations but **no AQI**. The public sample key is heavily rate-limited and
  returns at most 10 records, so the demo can show "rate-limiting" or "no rows for this city". The adapter
  surfaces official concentrations only; it never derives an official AQI. Generate a free key at
  data.gov.in for a stable demo.
- **Model AQI is an estimate.** Instantaneous CAMS fields are not CPCB 24 h/8 h averages, and no station
  observation is implied. This is stated in the UI, not hidden.
- **No indoor sensor input.** Indoor advice is source-control and sizing guidance; no indoor concentration
  is predicted.
- **Lighthouse and live deployment checks** require a deployed URL; they are not run in this environment.
- Rate limiting and caching are in-memory per instance, as noted in §9.
